# かんたん経費ノート ブラウザE2Eテスト ランブック

このスキルは、AIがブラウザを操作して「かんたん経費ノート」（確定申告補助・経費管理アプリ）の主要機能が正常に動作するかを検証するための手順書です。
※ ファイルアップロード機能（PDF/画像）のテストはセキュリティ制約上自動操作が難しいため、UIを通じた「手動入力」「分類」「サマリー出力」を中心にテストします。

## 準備事項
1. ローカル開発サーバーが起動していること（`http://localhost:5173/`）。
2. `browser` サブエージェントを起動して `http://localhost:5173/` にアクセスします。

## テスト手順

### 1. ホーム画面の初期表示確認
- URL: `http://localhost:5173/` にアクセスします。
- 画面上部に「かんたん経費ノート」という表示があることを確認します。

### 2. 手動入力機能のテスト
- 画面下部（または「手入力で追加」ボタン等）のUIから、経費を手入力する操作をシミュレートします。
  - **【重要】日付（<input type="date">）のテストについて：ブラウザの仕様上、通常のキーボード入力エミュレート（type/fill）を行うと不正な年（202608年など）になってしまいます。必ず JavaScript を用いて値を直接設定する（例: `page.evaluate(() => document.getElementById('date').value = '2025-10-10')` など）か、カレンダーUIを正確にクリックして日付を変更し、正しく日付が変更されることをテストしてください。**
- もしUIに「手入力で追加」の導線がない場合、開発中のUI仕様を確認し、手動入力用フォームを表示させます。
  ※現在のアプリ仕様では、Inbox画面に手動入力用のボタンや機能が存在するかどうかをまず確認してください。
  （もし存在しなければ、このステップはスキップして「テスト結果に『手入力機能が未実装または見つからない』と報告」してください。）

### 3. 未分類一覧（Inbox）での確認とモックデータの利用
- 現在アプリには初回起動時にデモデータ（モック）がいくつか登録されています。
- 「X件の未分類レシート」ボタン、もしくは Inbox 画面に表示されている経費のうち、1件を選んで「分類する ✨」などのボタンをクリックします。
- 分類画面（Categorize画面）に遷移することを確認します。

### 4. 分類画面（Categorize）での入力テスト
- 項目名、金額の入力フィールドに正しい値が入っているか確認します。
- 「事業割合(%)」のスライダー、もしくは入力フィールドを変更してみます（例：50%にする）。
- 「カテゴリ」のアイコン群からどれか1つ（例：「消耗品費」など）をクリックして選択します。
- 「この内容で登録する」または保存ボタンをクリックし、正常にInbox画面または完了画面に戻ることを確認します。

### 5. サマリーとエクスポート機能のテスト
- 画面下部のナビゲーションバー（TabBar）から「サマリー（Summary）」タブをクリックします。
- サマリー画面で、先ほど分類した経費の金額が「経費計上合計」に反映されていることを確認します。
- 画面下部の「データ管理」セクションにある「データをまるごと保存する 📦」ボタンをクリックします。
- ダウンロードが実行されることを確認します。

## レポート形式
すべての手順が完了したら、以下のフォーマットで人間に報告してください：
- **テスト実施日時**: [日時]
- **テスト結果**: [Success / Failed]
- **各ステップの状況**:
  - ステップ1: [OK/NG]
  - ステップ2: [OK/NG/Skipped]
  - ...
- **気づき・問題点**: [ボタンが見つからなかった、エラーが表示された等の詳細]
