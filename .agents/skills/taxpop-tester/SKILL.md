# かんたん経費ノート 自動テスト ランブック

本プロジェクトでは、AI（browserサブエージェント）による手動テスト操作から、完全自動化されたテストフレームワークへの移行を完了しました。
機能追加・修正を行った際は、**必ず以下の自動テストを実行して品質を保証してください。**

## 1. テストの種類と実行コマンド

プロジェクトには以下の2種類のテストが実装されています。

### ユニットテスト (Vitest)
ロジック（日付のパース、金額の計算など）を高速に検証します。
- **実行コマンド**: `npm test`
- **ファイル場所**: `src/utils/expense.test.js`

### E2Eテスト (Playwright)
ブラウザを自動操作し、画面遷移やUI操作（手入力、分類、サマリーの集計結果）を検証します。
- **実行コマンド**: `npm run test:e2e`
- **ファイル場所**: `tests/e2e/expense.spec.js`

## 2. 開発フローのルール

1. **コードの変更時**: 
   機能を実装・修正したら、必ず `npm test` と `npm run test:e2e` の両方を実行し、すべて PASS することを確認してください。
2. **仕様の変更時**: 
   新しい画面や新しい項目（例：新しいカテゴリの追加、必須入力チェックの追加など）を実装した場合は、それに合わせてテストコード（`expense.spec.js` 等）も必ず修正・追記してください。
3. **プッシュ時のブロック**:
   Huskyによる `pre-push` フックが設定されているため、テストが失敗する状態では `git push` ができません。万が一失敗した場合は、エラーログを確認してコードまたはテストを修正してください。

## 3. Playwright E2Eテストの注意点

- E2Eテストで特定の要素をクリック・検証する際は、曖昧なセレクタ（`locator('text=...')`）を使うと複数の要素がヒットしてしまい、Strict mode違反でエラーになることがあります。必要に応じて `.first()` を使うか、一意のセレクタを指定してください。
- （以前あったバグの教訓）「分類」操作では、カテゴリを選択した**後に**「事業割合（50%など）」のボタンが表示されるUIとなっています。テストコード上のクリック操作の順序に注意してください。

## レポート形式
AIとしてテストを実行した後は、以下のフォーマットでユーザーに報告してください：

- **テスト実施日時**: [日時]
- **ユニットテスト結果**: [Success / Failed]
- **E2Eテスト結果**: [Success / Failed]
- **気づき・問題点**: [エラーが発生した場合はその原因と対応]
