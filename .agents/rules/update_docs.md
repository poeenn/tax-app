# ドキュメント・テストコードの同期ルール

このプロジェクトでは、機能の追加や修正を行った際、必ず関連するドキュメントやテストコードが最新の状態を保つようにしてください。

## 必須確認事項
コードを変更したエージェントは、タスク完了を報告する前に以下のファイルを確認し、必要に応じて更新を行わなければなりません。

1. **`README.md`**
   - アプリケーションの名前や機能概要に変更はないか。
   - インストール手順やセットアップ方法に変更はないか。
   - 「次のステップ」や「未実装機能」などのステータスに変更はないか。

2. **テストスキル・テストコード（`.agents/skills/taxpop-tester/SKILL.md` 等）**
   - UIの文言変更によって、自動テストシナリオの指示書（ボタン名や画面名など）に食い違いが生じていないか。
   - 新しく追加された機能に対するテストステップを追記すべきか。

3. **設計ドキュメント・プラン**
   - アーキテクチャやデータ構造を変更した場合、過去の計画書や仕様書が古くなっていないか。

## エージェントへの指示
- ユーザーから機能追加や修正を依頼され、コードの書き換えが完了した後は、**必ず** `README.md` と `SKILL.md` の中身を `view_file` で確認してください。
- 矛盾や古い記述を見つけた場合は、自律的に `replace_file_content` などのツールを用いて最新の状態に更新してください。
- ユーザーへの完了報告時に、「コードの修正に伴い、READMEとテストスキルも更新しておきました」と一言添えることが望ましいです。
